⚠ **codex round 2-3 逼出的追加收敛(不是原始 R7 范围,是审出来的必要修正)**:

  `caliber_version` 读最新 verdict)。若未来 gate 被授权(`_CORRECTNESS_GATE_AUTHORIZED_V0_1`
  翻 `True`),会把这条只验过一个变体的 verdict 误读为覆盖了该 caliber 下全部变体。修法:新增
  `_assert_variant_scoped_verdict_is_safe()` —— 收窄到单一变体时,若该 caliber 下还有其它变体
  在场 → raise;该 caliber 下只有一个变体时(真盘当前形态)不受影响。**未**给 `gold_layer2_result`

- round 3:该检查最初放在 `reconcile()` 函数开头,与它守护的 `evaluate_layer2` 写入之间隔着 SLA

  check-then-write 竞态窗口(另一进程并发 census 写入同 caliber 新变体)。修法:挪到紧邻
  `evaluate_layer2` 调用之前,把窗口压到最小。**未**做成真事务(SQLite `BEGIN IMMEDIATE`
  贯穿检查到写完)—— 本仓明确是单 operator 顺序执行工作流(同 `produce-handback.sh` 已
  declared 的 "Known limitation" accept rationale),且 v0.1 `_CORRECTNESS_GATE_AUTHORIZED_V0_1`
  恒 `False`,gate 读取侧对这条 verdict 无论如何都不消费。代码注释已留痕残留风险与未来升级路径
  (若变多进程并发写入形态,须在此处补真事务)。

**R8**:`_assert_source_id_alignment` 对 `human`/`gold` 非 Mapping 元素(如盲标 JSON 某条被写成
数组而非对象)此前会抛裸 `AttributeError('list' object has no attribute 'get')`,只 catch
`BlindIsolationError` 的调用方会漏接。修法:先 `isinstance(seq[i], Mapping)` 判断,不符 → 统一
`BlindIsolationError`。
