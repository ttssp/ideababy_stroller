- **实测**:DeepSeek 真跑 200 条采样,58 条里 56 截断 + 2 返空 + 0 成功 → 无有效 accepted 信号 → 无法产出真密度读数(既非 below_threshold 也非 meets_threshold,而是**工具契约缺陷导致读数不成立**)。
- **根因**:proposer prompt 让 LLM 产原文字符偏移,推理型模型在长语料 + JSON mode 下烧爆输出预算截断。**这是框架级 spine 契约缺陷,不是 004-pB 项目功能问题** —— 撞面 = 所有用这套 census/extraction 跑真 LLM 抽荐股信号的项目。已按 dogfood 铁律记 XenoDev `dogfood-backlog.md` **KG-40**(high · 含逐字日志 + 根因 + 4 条建议),**未在 XenoDev 当场改**(改动牵动 extractor 引文锚定 C3 契约 = spine · 归 IDS forge)。

### 2. 两条候选修法均为 spine 契约级 · 须 forge 权衡(非 XenoDev 自决)

- **候选①(改输出契约)**:不让 LLM 产字符偏移,改产**信号文本片段**(逐字引原文子串 exact substring),偏移由下游 `extract()` 用 `str.find`/正则回锚定位。输出短得多 → 不撞 length。**代价**:改的是 extractor 引文锚定 C3 契约(现契约靠 LLM 给的 offset),改后靠子串回锚,需处理"子串在原文多处出现"歧义 → 走 typed rejection。
