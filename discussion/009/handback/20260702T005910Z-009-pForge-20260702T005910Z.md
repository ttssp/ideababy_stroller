## §3 Suggested IDS actions

> **本 hand-back 的核心 IDS action = 决策下方 2 条 spec 修订触发(prd-revision-trigger)。** T002 契约已 ship + codex approve,但下面两点若 spec 决定改,会影响 T003(查询引擎)/T012(M2 alpha)的实装契约,**宜在 T003 起跑前定**。

### 修订触发 #1(codex T002-R1-F2 · [high])· PIT 取价返回类型:标量 float vs 结构化 provenance
- **现状**:spec D-M1-2 / §7 P1 把 `get_adjusted_close` 签名定为返「复权收盘价」(标量);T002 忠实实装为 `-> float | None`。
- **codex 挑战**:返 float 丢失命中行的 `trade_date`/`as_of`/`source`/原始价+因子版本溯源;`None` 无法区分「无价 / 因子不可用 / 退市 / 状态缺失」。而 spec O6 / §7 P2 要求 M2 alpha「**as-of 可复现**」—— 标量返回让审计/回放只能依赖隐藏实现细节。
- **建议**(请 IDS 定):新增结构化返回类型(如 `AdjustedPricePoint(adjusted_close, hit_trade_date, hit_as_of, source, close_raw, factor_used)`),或让主接口返回含 adjusted_close + 命中行 provenance 的对象;可保留 float convenience 但建立在结构化接口之上。**影响**:改 D-M1-2/P1 签名契约 → T003 查询引擎 + T012 M2 realized-return 计算按结构化返回实装。
- **若维持标量**:需在 spec 显式记「as-of 可复现由 T012 自己另存命中 provenance 兜底」的降级理由(否则 O6 可复现性存疑)。

### 修订触发 #2(codex T002-R1-F3 · [medium])· PricePoint close-only vs 004 PriceBar 的 OHLCV/volume
- **现状**:T002 `PricePoint` 只建模 `close_raw` + 复权因子(对齐 T001 表列,T001 只存 close);但 spec C7/O4 要求 M1 PIT provider 满足 004 `PriceDataProvider.get_history -> list[PriceBar(date/open/high/low/close/volume)]`,且现有 feature 工程用 `volume`。
- **codex 挑战**:T003 实装 `CurrentStatePriceProvider` 时,只靠 close-only 契约要么伪造 OHLCV、要么返退化 bar、要么绕 PIT 层接第二价格源 —— 三者都破坏 O4「唯一价格源」+ C7 兼容边界。
- **建议**(请 IDS 定):二选一 —— (A) 扩 M1 schema/model/source 契约存 OHLCV+volume(T001 表加列 · T002 model 加字段 · T004/T005 源抓全 OHLCV);或 (B) 收窄 C7「004 兼容」声明为「仅 close 足够 xgboost lane 当前用途」+ 加测试防伪造 OHLCV 冒充真 PriceBar。**影响**:(A) 改 T001 表结构(已 ship · 需新 migration)+ T002 model;(B) 改 spec C7/O4 措辞 + 加 T003 守卫测试。
