## 3. 修正后的视角

- P1 判断 A「`-04` 成因是**登记顶替回写**,ledger 成了条款正文的替身」→ **被推翻(框法错)**。
  DO-178C 显示:**没有父需求的要求是一等公民**,只要带 rationale + 强制反馈 + 独立复审。
  OLRC 更进一步——**已生效但永不入正文**是合法状态,靠 Tables 维持可发现性。
  ⇒ `-04` 的病不是「没搬进 PRD」,是**ledger 行没有反馈边、没有复审主体、也没被裁定载体等级**。
  这同时改写我 P1 的推论「本轮五条里至少 `-05` 同病」——同病的判据要换成「有没有反馈边」。
- P1 判断 B「条件 1『至少一个』vs 条件 2『该市场』量词不一致 ⇒ CN/HK 结构性不可满足」→ **站住并被强化**。
  NCHS 的 n<30 抑制线让 CN 1/0/2、HK 0/0/4 在**任何公认标准下都落在 suppress 档**;
  B 侧提的 `not_estimable` 与 NCHS 的 `*` 同形。但 NCHS 多给一档我和 B 侧都没想到的:
  **「flag for review」中间态 + 具名 clearance official** —— 这正好回答 K④「字面满足算不算满足」:
  **算不算不由条款字面定,由具名主体在语境中判并留痕。**
- P1 判断 C「`-05` 应给**不产生数字的行为形态**」→ **半站住半被推翻**。
  站住的部分:不许看现数造 N。被推翻的部分:我把「控制图画不出来」等同于「过程监控做不了」——
  自启动图族**就是**为零历史设计的。⇒ 正确形态不是「不给数字」,而是**预注册方法族 + 明写 masking 敞口**;
  这与 B 侧三态(`insufficient_history` / `method_ready` / `recalibration_due`)可合并,且给了它缺的技术内容。
- P1 判断 D「`-12` 补一行不够,要声明 follow-up 对 decision 性质的影响」→ **站住,但我漏了一整维**。
  MEL 的 **repair interval 时钟**是我和 B 侧都没给的:两边都在争「该不该合法化」,
  而工业界的答案是**合法化 + 上时钟 + 授权人具名 + 修后强制复验**。ISO 9001 的「授权人身份必须记录」
  直接可写回 §4.2 表格。
- **元层(binding 歧义的处置)** → 本轮检索给了统一答案:OLRC(常设解释机构)、DO-178C(独立复审主体)、
  NCHS(clearance official)、PCI(书面指派 + 正式接受)、ISO 9001(授权人留痕)**五个体系无一例外
  把「谁有权解释/放行」写成具名主体 + 留痕**,而没有一个靠条款把状态空间穷举。
  ⇒ 本轮五题的共同解法不是「把选项集补全」(不可能穷举),而是**为每类条款配一个具名解释者 + 强制留痕**。
  ⚠ 这条撞上本仓已在册的 **KG-42 同族问题**(本仓只有一个人,具名 = 自任)——**必须在 verdict 里明写,
  不得当作已解**。
