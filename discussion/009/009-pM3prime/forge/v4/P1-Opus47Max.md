## §1 现状摘要(按 Y 三视角)

### 工程纪律

条款歧义的四处载体我逐字对照过,**结论比 K 的描述更不利**:这不是「一份文档里有两句话打架」,
而是 **广读出现在三处(v3 正文 :277、decision matrix :163、ledger 标题),窄读只出现在两处
(v3 结果矩阵表、ledger note)** —— 少数派口径赢了。且赢的方式很具体:decision matrix 那行
把消费点写成 `forge:009-pM3prime:phase0`(**已接线**),而 T015 hand-back 读的是结果矩阵表。
**多数载体 + 已接线的消费点,输给了一张更靠近执行者的表。**

更值得记的是:**这一轮 gate 真的开火了**。四条义务在 `forge:009-pM3prime:phase0` 被拦住,
warn 也被拦住。v9/v10 机制**第一次证明它有齿**。但同一次开火里,我撞到两个自指缺陷:
(a) fork 域 `temporary` warn 的「给出新 due_event 的 defer」**不可表达**(validator 到期判据不含
「是否已裁决」,而 fork 域唯一接线的消费 gate 就是当前 gate);(b) obligation gate 要求在 intake **之前**
取得终态,而它自陈的 evidence 形态是「已并入本轮 X 第 n 项」——**在定义上要求 X 已存在**。
两条都是「判据与其自身要求相反」,与 KG-B21 同族。

### 架构设计

`census.py:728-731` 的 docstring 是本轮最硬的单条证据,逐字:

> ⚠ **为什么必须独立于主事务**:RETRY-CONTRACT §2 主判据是"重试耗尽仍失败的 record 是不是同一条,
> **跨批次比对**" —— 而触发 census_invalid(整轮回滚)的失败,恰恰就是这里要记的那类失败。
> 若记账随主事务一起回滚,证据会在它第一次发生……**永久消失,判据永远算不出来**
> (RETRY-CONTRACT §5:"**不做这条,前面全是空话**")。

⇒ **代码作者自己写明:`extraction_attempt_log` 存在的理由就是跨批次比对。**
这直接落在 IDS 第 35 条的谓项上,而不是 T015 §5 的谓项上。

更进一步:`attempt_log_persist_failed`(:171-176)是 round-7 为**同一风险类**加的 ——
docstring 原文「跨批次判据(同 record 是否反复失败)会悄悄基于缺失数据运算**而不自知**」。
**但这个字段在崩溃场景下结构上无法开火**:它是 run 正常返回时由 `run_census` 打的标;
进程被 SIGKILL 时既没有返回值也没有标。⇒ **为「不自知」而设的告警,在 T014 finding (a) 描述的那个场景里恰好静默。**

### 测量效度 / 统计方法学

M1=pass 的数字我不复核(已复证)。但**读数的形状**有一处此前无人提及:
PRD §6「科学重判触发条件」第 1 条要求「产出**至少一个 per-market** 的跨次一致性读数」;
而 T015 的结果矩阵 **`'market' in json.dumps(d).lower() == False`** —— 全局 J_1 = 0.4078 / J_agg = 0.6885,
**零 per-market 分解**。上游 `trial_ledger` 恰恰是 `market×horizon` 9 行的 grain(`aggregation_probe.py:734`),
即分解所需的数据在库里。⇒ **CN/HK 科学重判的条件 1 并未因 T015 而满足**,而 hand-back 与
第 36 条都没说这句话。

另一处:forge v3 §underweights 第 3 条**事先写明**了本次结果的决策价值 ——
「3.5 小时可能买到的是『本批上聚合有改善,但不能外推』——**这在决策上接近于零**」。
**这正是发生的事。** v3 自己给 M1=pass 定的价签,与 hand-back §1 把它放在标题位的呈现方式,不在一个量级上。
