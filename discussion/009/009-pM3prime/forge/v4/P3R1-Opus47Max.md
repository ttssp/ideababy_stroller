## §1 整合摘要

**双方 P1 四题倾向逐条相同(连续第四轮),但双方 P2 各自推翻了自己 P1 的一部分** ——
A 侧四条(pass 非中性 / 按事件也是启发式 / 判据形态只对一半 / 撤回外部规范支撑),
B 侧三条(每批监测 ≠ 每批重校准 / 写穿透非唯一解 / convert 不必先证普适映射)。
**且 B 侧检索面与 A 侧零重叠**(A:标注分歧、ML drift、OPA、Chrome、预注册;
B:NIST 计量学、RFC 5848/9162、ModSecurity、Kubernetes KEP)。⇒ **P1 的收敛是回声,P2 的收敛不是。**

**本轮最有价值的单条外证据是 B 侧的 NIST**:测量过程处于统计控制时,
「**can only guarantee comparability among measurements**」——不保证准确。
它与 A 侧的 disagreement-as-signal 文献**从两个方向夹住同一结论**:
M1=pass 证明的是**可比性**改善;而一致率上升**无法区分噪声去除与歧义抹除**
(「filtering non-consensus samples results in over-optimistic results」)。
⇒ 两条独立证据链共同支持:**pass 不得作为效度 gate 的代理,且其 rationale 必须写明方向性风险**。

另一条 B 侧发现值得单独记:RFC 5848 / 9162 提供缺口可检测审计,但**审计失败后的动作不规定**。
⇒ **议题⑤的形态不是本仓独有的纪律问题,成熟标准同样止步于「机制有、动作无」。**
这改变处置方向:重点不在继续找第五处、第六处,而在**动作绑定**本身。

## §2 我的初步 verdict

**四题合起来是同一条**:本 fork 反复把「机制存在」当成「行为会发生」,而四条到期义务是它的四个断面。
**①** pass **欠**一次具名裁决(广读),但依据只能是本地三载体 + 已接线消费点 + `OB-16` 本身,
**不得援引外部规范权威**;裁决内容必须包含方向性风险,不得只写「不解锁」。
**②** 现状**不可信**——但义务应写成**判据**(可作有删失的失败率估计所需的前提),**不是**写死「写穿透」。
**③** 周期**现在定不出来**,能定的是「开始积累 control history 的机制 + 身份变化立即启动新基线」。
**④** convert 判据 = **过程证据 + 结果证据 + 具名批准 + 可回退,四者合取**;不给数字。

## §3 关键分歧清单

### 分歧 1 · `OB-15` 该写实现还是写判据(**我让步**)

- **我的 P1/P2 立场**:至少 finding (a)「不可 defer」,落点是把 attempt log 改成写穿透。
- **对方立场**:「**写穿透不是理论上的唯一解**」;若崩溃被显式标为具有已知 exposure 的删失、
  且内容身份可证,跨批估计可能成立(NIST censored analysis,但其前提是
  「**exact times of failure are recorded**」)。
- **我的裁定:采对方。** 这正是 memory `forge-verdict-vs-empirical-ship` 的正面解法形态
  ——「A + 判据 + 证不出则 B」。写死实现会重演 v3 §underweights 1 批评过的
  「(a) 没写 fallback」。**R2 收敛方向**:`OB-15` 的兑现判据写成三个前提
  (① 观察边界预先固定 ② exposure 可计 ③ 失败批次内容身份可证),
  实现路线交 build 侧选,**证不出三前提则回退到写穿透**。

### 分歧 2 · ③ 现在能否定出一个可写的校准周期(**我更保守,需对方压**)

- **对方立场**:给出可写形态——每个消费批次监测;重校准由长期 control 数据相对应用要求决定。
- **我的立场**:该形态**正确但当前不可执行** —— NIST 的 control-chart 路径要求**多点历史**,
  而本仓全部可用点是:两跑 Jaccard 0.44、本次 J_1=0.4078、历史密度 41/73/71。
  **控制图画不出来**。⇒ 此刻能定形的只有 (i) 每批必测并落库以**开始积累** control history、
  (ii) 身份/口径变化(模型、`system_fingerprint`、语料批次、`caliber_version`)**立即**启动新基线、
  (iii) **周期本身显式标为「待 control history 达 N 点后回填」**。
- **R2 期望**:若对方认为「现在就能定周期」,请给出用**现有 1-3 个点**定周期而不落入
  「看数后设门槛」的具体路径;否则收敛到我的三段式,并把 N 的取值列为 v0.2 note。

### 分歧 3 · ④ 的「可回退」与本仓 C6「预注册不可回改」正面冲突(**对方未处理**)

- **对方立场(新引入)**:Kubernetes KEP 把 graduation criteria / flake-free e2e / PRR 批准 /
  **rollback metrics 与测试**列为**并列必填**;ModSecurity 要求 DetectionOnly 期真实误杀审阅。
- **我的立场**:方向同意,但**本仓做不到 rollback** —— C6「预注册不可回改」+ v2「移动球门」判据意味着
  **一旦 convert 成门禁并升 `caliber_version`,退回 report-only 会被自己的反自欺条款挡住**。
  ⇒ **convert 在本仓是单向门**,而工业先例把可回退当作 convert 的**前提**。
- **R2 期望**:这是本轮唯一双方都没解的结构性冲突。两条出路:
  (a) 承认单向 ⇒ convert 的证据门槛必须**高于**工业先例(因为错了不能退);
  (b) 设计一个不违反 C6 的回退形态(如:回退 = 再升一个新 `caliber_version` 且旧 gate 结论作废而非篡改)。
  **我倾向 (b)**,因为 (a) 会把 convert 推到永远达不到。
