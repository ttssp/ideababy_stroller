## 1. 现状摘要(按 Y 视角组织)

### 视角 A · 科学效度(测量工具)

E1 的核心产物是一个叫「密度」的量,它在 PRD §6 里以**标量**身份参与判决:
`per-market` 与预注册阈值比大小,产出 `US ✅ / CN·HK ❌ STOP`。

而 §10.5 的三次读数显示它不是标量。同参同输入,同日两跑 accepted = 73 / 71,
跨周 41;按 `(source, ticker, direction)` 去重后同日两跑 **Jaccard 0.44**;
7 月那 32 个元组在今日两跑中**都**出现的只有 50%。
分市场层更糟:总量只差 3% 时,HK 从 0 变 4、CN 从 0 变 2。

PREREG 自己完成了一次值得记录的自我更正:初版用 **span 条数**度量稳定性(12/12/12/12,
看起来很稳),换成 **`{(ticker,direction)}` 内容集合**后变成 4/4 全不同。
**同一个对象,粗指标显示稳定,细指标显示不稳定** —— 这不是测量误差,是**指标选错了**。

### 视角 B · 架构设计

`census.py` 的失败处置是这样的:LLM 调用的三类失败(api / parse / truncation)累加进一个
**run 级共享 `stats` dict**,`_has_census_invalidating_failure` 的判据是**任一计数 > 0**,
命中即整轮 `census_invalid` + 全回滚 + exit 非 0。这是 KG-40 的正当反应,设计意图无误。

但它是一个**二值门**,而它面对的是一个**规模敏感的伯努利过程**。实测 p≈0.17%:
n=120 时 P(通过)≈82%,n=1364 时 ≈10%(§10.4 实算),叠加 §10.5 的第二次失败后 operator 估到 ≈1.5%。
**同一条规则,在两个规模下语义完全不同**:小样本上它是「工具坏了就别信读数」,
大样本上它是「几乎必然作废」。规则本身没变,变的是它被应用的地方。

同一层还有第二处二值化:`_N_MAX = 12` 是**硬截断**,而 §10.6 观察到它**几乎每次被顶满**——
一份 388 字符、纯财报数据、零推荐语的记录也稳定提出 12 条。
上限被顶满意味着**提案层处于饱和态**,而饱和态下「哪 12 条被留下」没有任何稳定性保证。

### 视角 C · 工程纪律

`system_fingerprint`(实测值 `fp_a18b46594c_prod0820_fp8_kvcache_20260402`)由 API 返回、
`resp` 对象已在手,`census.py` 读了同一个 `resp` 的 `usage` 却**从不读它**;token 总量也从不累计。
`extractor_variant` 的身份定义(forge v6 条款 D = proposer 类型 + prompt 模板版本)
**不含模型权重** —— 这不是疏漏,是一个**旧裁决在新证据下暴露了边界**。

**而我在 X 之外主动核了一件事,结果比上面几条都重**:
PRD §7 红线 3 写的是「温度 0 / 提取器版本化 / **同文本同版本必须同输出(一致性测试)**」,
§8 要求契约测试覆盖 §7。这条测试**存在且常绿** —— `test_e1_citation_consistency.py::test_same_text_same_version_same_output`。
但它把 proposer 换成了 `literal_ticker_proposer`(正则、构造上确定),
docstring 自陈「温度 0 · **literal proposer 确定性**」。
另一侧 `test_llm_proposer_wiring.py` 覆盖了 LLM 路径的 20+ 个失败分类分支,
其中 `test_should_call_deepseek_with_temperature_zero_and_json_mode` 断言的是
**`temperature=0` 被传给了 API**。

⇒ **红线的两半各自被测,而红线本身落在两半之间的缝里**:一半证明「确定性 proposer 是确定的」(恒真),
另一半证明「参数传对了」。**没有任何测试断言产线 LLM 路径同输入同输出。**
更糟的是,这条缝产出的是**正信号**:一条绿的 contract test,挂在一条 BLOCK 级红线下面。

`extractor_variant` 假定一个名字对应一个固定对象、C4 测试假定「温度 0」蕴含「输出相同」。
**「温度 0 ⇒ 确定性」这个代理关系是整条链的地基,而它今天被实测证伪了。**

## 3. 我现在最不确定的 3 件事

1. **不稳定的机制归属** —— 三个候选处方完全不同:(a) 模型采样本身非确定(batching / MoE routing /

   (b) 我认为可**零成本证伪**:放宽 `_N_MAX` 后看提案数分布是否仍顶满。
   (c) 是最坏情形 —— 若口径在提案层根本没有约束力,那 caliber v1 的「五要件」只在**筛选层**起作用,
   Layer-1/Layer-2 整个金标框架就建立在一个欠定的提案分布上。
   **希望 P2 搜到:IE / LLM-annotator 领域怎么把这三者分开归因。**
