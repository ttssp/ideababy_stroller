## §1 现状摘要(按 Y 视角)

### 工程纪律 —— 四条的机制侧**全都是写对了的**,失效整齐地落在同一层

这是我 P1 最强的一个观察,且它改变问题的性质:

- **R-Q7**:`codex-review/SKILL.md:279-317` 有完整双写范式、`:315` 把「只写 singleton 不产
  immutable」**明文列为 ❌ anti-pattern**、`write_review_log_immutable` lib 真实存在。
  **文本、判例、工具三样齐全 —— 结果 16 轮零记录。**
- **XD-43**:preflight 解析器已实装且本轮还被收紧到 fail-closed。**门造好了,没有入口调它。**
- **XD-41**:替代路径**每批都跑了**红绿日志 / mutation 验牙 / 双子代理评审。**动作全做了,判据太松。**
- **XD-44**:4 轮上限是明文规约,operator 两次**如实破例并留痕**。**纪律遵守了,数字定错了。**

⇒ 四条**没有一条是「设计没想到」**。它们全部是**「想到了、写下了、造出来了,然后在执行面蒸发」**。
这直接推翻一个默认假设:本批不是 design gap,是 **execution-evidence gap**。
**修法若停在「把文档改对」层(改 SKILL 措辞、加一行清单),会精确地重复已经失败过的那件事。**
—— 这一条我认为是本轮 verdict 的地基,请 Codex 优先证伪。

### 架构设计 —— 「缺席即豁免」的真正结构:**判据在检查对象,豁免在解释意图**

三个实例(XD-43 门没人调 / KG-B11 记录没人写 / precheck 块没人带)共享一个精确的错误:

```
实装判据  = 「这个东西在不在」        （grep -q '^ids_verdict_evidence:'）
豁免理由  = 「这类对象本来就不该有」  （老 hand-back / 非 build-ship 包无此块属正常）
```

**两者被当成了同一件事,但它们不等价。** 一个**声称跑了 11 轮 review 的 2026-08 build-ship 包**,
只要不写那个块,就自动落进「本来就不该有」的豁免。⇒ **缺席同时是「不适用」和「违规」的证据,
而系统总是选前者解释。**

K 第 3 条已经把死路堵上了:`SHARED-CONTRACT:993` 的 known-gap **一手验证过**,字面严格化
(缺即 REJECT)会对每个合法老包误拒。所以真正缺的是一个**独立于被检查对象自身的预期声明**
—— 因为对象缺席时无法自证「我该不该在场」。**这是本轮的核心架构问题**,四条都撞它。

### 安全 —— 威胁模型不是恶意 operator,是**系统性乐观偏差**

- **stale pointer 是错误的正信号**:`REVIEW-LOG.md` 至今对下游显示 `approve / findings_count: 0`,
  而现实是 `needs-attention` 带 2 条未复核 high。**丢失是空(会被发现),反向正信号是假绿(不会)。**
- **XD-41 的「产物能说谎」族**:默认 False 的来源声明布尔 ⇒ **什么都不做就等于声称真跑**。
  这与「缺席即豁免」是**同一个偏差的两种铸型** —— 默认值和缺席值都朝「通过」方向解释。
- ⇒ 威胁模型应写成:**在一个每个缺口都朝通过方向默认的系统里,不需要任何人作恶就能得到假绿。**

### ⭐ §1 附加发现 —— 本家族的第四个实例,就在协议文本里

`SHARED-CONTRACT.md:993` 之后挂着一段 **post-P0 backlog**,明写:

> 三处同根缺口……(1) consumer shallow 只验语法 · 但本段 normative 仍说要验可达+rehash →
> **contract 内部矛盾**;(2) 绑 singleton 的 hand-back 下次 review 覆盖后无法复证;
> (3) **replay 窗口**……post-P0 方向:(a)…(b) shipped hand-back 强制 immutable review_log_path
> 拒 singleton;(c) 校验 bound log == 当前 latest 堵 replay;(d) hand-back 携带 IDS 可独立验证的
> review artifact。**需 forge 决议是否升级 + 是否改 R-Q7「策略 A」为「只绑 latest」。**

**它写着「需 forge 决议」,登记于 2026-05-31。forge v5 / v6 / v7 / v8 一场都没接它。**
到今天 **65 天**。⇒ **一条显式登记、点名要 forge 裁的待办,因为没有机器落点提醒它存在,
静默地等于不存在。** 这是「缺席即豁免」的第四个实例,而且发生在**治理层自己身上**。
更要紧的是:**它列的 (b)(c)(d) 与本轮四条高度重叠** —— 本轮若不把它一并接手,就是第五次。
