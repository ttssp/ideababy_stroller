## §1 · 整合摘要

**双方在 P2 后已高度对齐,而对齐的达成方式值得记录:两次都是我被纠正。**

Codex P2 跑 24 queries 取到 5 条锚点,**独立到达 RFC 1589**(我在 P2 对它封存了该内容)——
这是**真收敛**,不是事后同意。它还在三处把结论推得比我远:

1. **PEP 387 给出了我缺的那一半**。我 P2 的结论是「关键区分是**被裁决出来的 defer** vs
   **被遗忘的 defer**」;PEP 387 的 soft/hard deprecation 分型说明:**并非所有 warn 都要升级** ——
   **永久 `defer` 可以合法,但必须显式标为 soft 并承认无移除计划;只有临时 warn 才必须带
   due event 与 owner**。⇒ 真正的缺陷不是「warn 没有到期」,是**「warn 从未被分型」**。
   本仓三个 warn(`check-7` / `check-8` / worktree preflight)**全部未声明自己是哪一类**。
2. **Ruff `RUF100` 直接反驳了我「只减不增没有工具可执行」的诊断**。失效的 `noqa` 压制
   **可被机器识别并自动删除** ⇒ 例外回收**是可工具化的**,KG-B19 不是「等人过表」的宿命。
3. **Sonar new-code baseline 给了追溯性执法的成熟解**:PR 只对相对 baseline 的**新代码**
   施加失败条件,**旧债不被追溯阻断**。⇒ `check-8` 的 47/100 存量包问题有现成形态,
   不必在「全库翻硬」与「永远 warn」之间二选一。

**两条对我不利的判定,我都接受**:
- **(a) 关键性分级假说 —— 证据不足。** 研究支持按**变更风险信号**分配注意力,
  但**不支持静态模块分类,更不支持据此设不同轮数**;T041 vs FU-R5F4 的 n=2 不能决定修法。
- **(b) 我第二次偏袒被判中。** 我 P2 据「本仓机制 ≈ SOTA 形状」提高了对 v9 的评价,
  Codex 判:*相似数据模型不等于相似 enforcement coverage* —— 9/11 obligation 无 consumer、
  无自然时钟。**这是同一偏袒的第二次发作,它两次都判中了。** 我撤回该评价提升。

## §2 · 我的初步 verdict

**核心是一条本仓从未有过的分型,不是又一个 check:每一条 `warn` 必须在诞生时声明自己是
「soft advisory(永久 defer · 显式承认无移除计划)」还是「临时 warn(必带 owner + due event +
消费该 due event 的 gate)」;未声明分型的 warn 不得新增。** 「复发 ≥N 次」全部作废 ——
它不是升级机制(无计数者、无消费点、无执行者),三条现存判据应就地改写为分型声明。
配两条边界条款:**存量与新增分域**(forward gate 硬拦新包,历史语料只读不追溯,承 Sonar baseline)
与**例外回收工具化**(基线比较 + 自动拒新增/清除失效,承 Ruff RUF100)。
**v9 obligation ledger 是这些义务的交付承载面,但不是语义定义面** —— 它管「不被忘记」,
管不了「review 怎样算终止 / 怎样证明真跑 / 谁拥有路径真值」,后者仍是新结构。

## §3 · 关键分歧清单

**分歧 1 · XD-44′ 修法方向(本轮最实的一条,双方都未定案)**
关键性分级已被否,Codex P2 指向「按**变更风险信号**分配注意力」(JIT 模型 68% accuracy / 64% recall)。
**我的立场:反对把风险预测模型引进本仓作 gate 判据** —— 单 operator 仓无训练语料,
且 68/64 的量级不足以承担放行职责。**我主张走终态语义**:区分 `approved` /
`exhausted-with-open-findings` / chair-override 三种可消费终态,由 ship gate 直接拒绝同形放行。
**⚠ 这其实是 Codex 自己 P1 的主张**(其 XD-44′ 行原句:*ship gate 直接消费终态并拒绝同形放行*),
它 P2 的 SOTA 又引出了风险信号这个新选项。**R2 请它明确:两者取一,还是分层并存?**

**分歧 2 · KG-B19 评级**
我 P1 判 `new`(两条框架规约互不兼容需架构级消解),Codex 判 `refactor`(先按 checkout 根归一,

**分歧 3 · KG-B16 评级**
我 P1 判 `keep`(已止血,只剩追认 + mirror 同步),Codex 判 `refactor`,理由是

「单侧实装被当成已落地」,若不补收据,同一形态会原样复发。
