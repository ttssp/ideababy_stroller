## §3 修正后的视角

**站住的(P1 → P2 不变)**

- 分区键是「同一集合」的定义而非实现细节,必须前置冻结 —— Cochrane 从准入侧独立佐证。
- 「留 T041」是错配(P1 §1-B1)—— SOTA 未触及,但 task 原文事实未变,维持。

**被 SOTA 修正的(三条 · 均削弱我 P1 的原判)**

1. ⭐ **我 P1 §1-B3 的框架错了。** 我写的是「『不自行改』被等价成『所以可以合』」,隐含
   「反对未消解就不该合」。RFC 7282 明确否定这条:**推进是合法的,前提是 addressed 而非 merely noted,
   且由 chair 认定。** ⇒ 修正后的判断:
   - amendment **确实**写了实质理由入 spec 正文 ⇒ 在 RFC 的意义上**接近 addressed,不是 merely noted**;
   - 但**两件缺失是真的**:(i) reasoned explanation **从未回给反对者**(codex 侧无回路,五轮各自独立);
     (ii) **认定者 = 被反对方自己**(spec-writer 自判「超授权 ⇒ 可披露放行」),**没有 chair**。
   - ⇒ **本轮该造的不是「needs-attention 必须阻断」,是「谁是 chair、chair 的认定要留什么痕」。**
     这也解释了为什么 config 禁「已显式披露」作判据是对的:**披露 = noted 侧,不是 addressed 侧**。
2. ⭐ **「标注 + 通知」不足以处理已放行结论。** 撤稿实证(标了仍被引)直接打在我 P1「可撤销/版本化」
   与 GPT 洁净 P1「`suspended-pass` 队列 + 下游不得当 PASS 消费」上 —— 两者都假设下游会遵守标记。
   ⇒ **追溯必须落在消费点的 fail-closed 判定上**(消费方读到非 clean 状态即拒),
   **不能落在通知/标注机制上**。这条对 GPT 洁净 P1 的第 2 行 fallback 是实质加强,不是否定。
3. ⚠ **阈值「≥3」本身进入了争议面,而本轮无视角审它。** Cochrane 说少量研究的分组探索无论 timing
   价值都存疑。这打的不是分区键,是数字本身。**我 P1 与 GPT 洁净 P1 都默认了「≥3」正确,只争怎么分区。**
   ⇒ 本轮 **Y 未选产品价值视角**(operator 明确不选),v5 §underweights 也自认没回答「1 条判断
   对 operator 有无决策价值」。**该面本轮不判,但必须显式挂账**,不得因双方都没提就消失。

**GPT 洁净 P1 未到达、而我 P1 有的四条 —— 现降级为「我的单方主张」待 P3R1 对撞**
