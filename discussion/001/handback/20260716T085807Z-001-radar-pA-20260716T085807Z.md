## §1 Rationale(执行摘要)

**结论(先)**:forge 001 v1 verdict 要求「落地前先用一次真 briefing 验证三项 checker 秒级可判性」(stage 文档 §underweights 回声室预警明写)。XenoDev 执行了这个硬前置真跑,**结论:三项验收里的 ①(trace/provenance schema 完整性)与 ②(证据 3 击可达性)在当前 pipeline 拓扑下做不到秒级机器判 —— 不是 checker 难写,是可判的底料在真 briefing 里根本不存在**。按 forge verdict 自己的 STOP 条件(「任一项做不到秒级机器判 → 回 IDS 重审该项资格,触发 forge v2」),**不硬改**,产此 hand-back 回流。

背景:forge v1 verdict(`discussion/001/forge/v1/stage-forge-001-v1.md`)采纳 KG-B8,把 P0.2「人肉盲测二值签字」gate 退役,新 T010/T011 解锁前置改为「机器可自动判最小验收三项」。PRD 已改到 v1.3(`.../001-radar-pA/PRD.md` O4 重写)。stage 文档 §underweights 把「回声室 + 未真跑验证」标为主要盲区,并列为触发 v2 的头条:「① XenoDev 真跑发现三项 checker 无法秒级机器判 → 推翻『机器 smoke gate』可行性」。本 hand-back 就是那次真跑的结果。

真跑用既有产物 run-877f1c1e(`out/reconstruct/diffusion-models-20260713T133341Z.md` · 封闭窗 2021→2023 · 真 OpenAlex + 真 DeepSeek),不重跑烧 key。核验路径:直接读 domain/gate/reconstructor/writer/injector/CLI 源码 + DAG task 依赖 + 一个独立对抗子代理交叉核验,两条独立路径**逐行一致、零分歧**。

**核心发现 = 循环依赖**:forge 想用「对 trace 的机器判」取代「人肉盲测 gate」,但**能产出机器可解析 trace 的 pipeline 环节(T011 图 + source 锚 / T021 证据链 + source_ref 真解析)恰恰是 gate 下游、被这同一个 gate 所 gate 的东西**。checker 的底料 ⊂ gate 所 gate 的范围。用真 briefing 秒级判 ①②,物理上要先让 gate 开——而 gate 开正是 ①② 想取代的判据。

诚实标注(reviewer 应知):项目内 gate/pipeline 代码**保留不动**(不静默改 · 防 V4)。本 hand-back 只回流真跑发现的可判性缺口,不落地 forge refactor plan 四模块(A/C 依赖 ①② 底料 · 前提不成立 · B/D 不依赖但单独落地无意义 —— 详见 §3)。gate 仍未 PASS,T010/T011 维持 blocked(STOP 铁律不变)。

## §2 触发原因 + 决议链(按 frontmatter `tags` 逐条说明)

tag = prd-revision-trigger:forge v1 verdict 的「机器可判三项」新前置,其中 ①② 的机器可判性在真 briefing 上不成立,触发对该 verdict 该项资格的重审(forge v2)。决议链如下,证据可逐条回溯(对齐 O2 主锚精神)。

### 真跑证据(逐条 · file:line 可溯源)

1. **真 briefing 里零 trace 底料**:`projects/001-radar-pA/out/reconstruct/diffusion-models-20260713T133341Z.md`(2150 字节)整篇只有「方向名 + 位移叙事散文 + 3 个切片的 structural_state 文字」。grep 任何引用类 token(https?://|doi|arxiv|10.xxxx|slice://|node://|source)= **0**。checker ①② 无字可解析。

2. **底料被管线丢掉了(类型齐全 · 但未喂进产物)**:
   - provenance 类型定义齐全:`SourceRef`(ref: URL/DOI/arxiv)、`EvidenceLink`(hops: int = Field(ge=1, le=3) = 「3 击」类型)、`MethodClaimNode.source_ref`、`Judgment.evidence` —— 都在冻结 domain `src/radar/domain/__init__.py`。`Paper` 也真带 `source_ref`(OpenAlex DOI/URL 可解析 · `retrieval/models.py:25` + `openalex.py:80`)。
   - 但 gate 消费、writer 渲染的 **`TimeSlice` / `DisplacementNarrative` 不带任何 source 回链**(domain L89-210:TimeSlice 字段 = slice_id/period/structural_state/is_negative_control · DisplacementNarrative 字段 = direction_name/slices/narrative/sparse_coverage)。gate 自己的源码注释坐实:「本 run 数据模型无 per-slice source 映射可信 · TimeSlice 不带 source_ref」(`credibility/gate.py:219`)—— 这正是 gate 在重跑模式**拒 doc:// / node:// 锚**的理由(gate.py:157-162 / 215-221)。
   - CLI 真跑时图是**空传**的:`MethodClaimGraph(nodes=(), edges=())`(`cli/reconstruct.py:98`)—— 连 MethodClaimNode.source_ref 这条锚路径在运行时都是空的。
   - 管线**丢弃 paper→slice 映射**:papers 有可解析 ref,但 slicer→reconstructor 只保留时间窗 metadata + LLM 提炼的 structural_state,论文本身在 LLM 调用后被丢(`reconstruct/reconstructor.py:241` model_copy 只回写 structural_state)。

3. **根因 = 循环依赖(DAG 机器可查)**:能产出机器可解析 trace 的能力恰恰是 gate 下游:
   - **T011**(`src/radar/graph/**` · 图 + source 锚)`depends_on: [T004-A1]` · 硬前置 = 「存在 P0.2-RERUN-PASS verdict=PASS」(`tasks/T011.md:6,20`)· 产出注释「每节点/边挂 source 论文锚点(future evidence chain 的图侧锚 · 供 T021)」。
   - **T021**(`src/radar/evidence/**` · 证据链 + source_ref 真解析)`depends_on: [T020]`(更下游)· 验收测名字面就是 checker ①②:`should_link_each_judgment_to_source_within_3_hops` + `should_resolve_source_ref_to_real_retrieved_document`(`tasks/T021.md:40`)。
   - 链路:`T004-A1(gate PASS) → T010/T011 → T012 → T020 → T021 → T022`。三个模块 `src/radar/{graph,evidence,journal}` 磁盘上都**不存在**(未建 · gate-PASS-gated)。
   - §7 PPV 亦坐实:P1(gate)「必经环节」列了「真方法/claim 级图构建」,但那是 T011(gate 下游);而 gate 实际跑的是 P0.1(retriever→slicer→narrative · RT-2 明示「judge/briefing 不在 P0.1」),所以 gate 时图不存在、真 briefing 无 trace。§6 O2 行说的「一份真 briefing 抽 ≥3 条判断……每 source_ref 命中真检索语料」指的是 **Phase 2 的判断 briefing**(带证据链),不是 gate 消费的**盲测位移叙事**。两者是不同产物。

4. **这正是 forge 自己预警的盲区兑现**:stage 文档 §underweights「convergence_mode 副作用(回声室)」明写:「①『机器可判三项秒级可跑』是**推演**,未在 XenoDev 真跑验证——trace 完整性/引用可达性的机器判定在真实 briefing 上可能比想象的难(参考历史教训:forge 理论决议屡漏实证盲区,DB 引擎语义/并发/原子性靠真跑才现形)」,并「建议 verdict 落地前在 XenoDev 用一次真 briefing 验证三项 checker 的秒级可判性,而非直接信推演」。真跑把这个盲区证实了。

### 诊断信号(供 IDS forge v2 参考 · 本仓不决策)
- **①② 与 ③ 的分层**:checker ③(轻量文件级审计通道)本身可独立建(不依赖 gate)· 但它是给 operator 抽查「trace」用的**载体** —— 没有 ①② 的 trace,③ 是个空壳通道,抽查无物可查。所以这不是「①② 稍调就过」,而是**整个『机器判 trace』前提在当前 pipeline 拓扑下不成立**。
- **与 KG-B8 的连续性**:2026-07-15 operator 真跑当面拒的正是「盲测二值签字」形态,要的是「留痕可审计 · agent 留 trace · operator 抽查」。forge v1 把这落成「机器判 trace 三项」—— 但 trace 底料的产出被 gate 挡在下游,操作上 operator 想要的「边用边抽查 trace」也拿不到 trace。两个 STOP 指向同一结构症结:**trace 能力在 pipeline 里的位置不对**(排在 gate 之后 · 而验证 trace 又想在 gate 之前)。
- **深层反讽(承接 KG-B8)**:forge v1 已明确「别重蹈 T004-A1 花 14 轮硬化被 B8 推翻前提的过度投资」。本次发现同理:若直接落地模块 A/C(机器 trace checker),会先建一套 checker,再发现它没底料可判 = 又一次过度投资。真跑前置正是为了避免这个,现已挡下。
