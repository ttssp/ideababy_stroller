## §1 Rationale(执行摘要)

**T042 三态结果接口 + 消费点 verifier** —— spec §1-O2(c) gate-level 声明表 **PASS 转正条件④** 的 owner 已落地为代码。

收口前 `evaluate` 命中 `INSUFFICIENT_EVIDENCE` 时机器侧仍是 `exit 0` + 正常落盘,下游自动化**无从区分**「真正可放行」与「命令只是没崩溃」。本 task 交付:

1. **三态 `ResultStatus`(PASS / INSUFFICIENT_EVIDENCE / FAIL)+ 独立命名空间的 CLI 退出码**
   `3`=FAIL · `4`=INSUFFICIENT_EVIDENCE · `5`=PASS∧warn · `0`=PASS∧block;既有 `1`(未检索到论文)/ `2`(dry-run·注入配置错误)**原义不动、不复用**。两个命名空间由具名回归测遍历真早退路径钉死。
2. **`VerdictArtifact`** 落 `out/verdict/<方向slug>-<run_id>.json` —— **不绑定 briefing 是否存在**(FAIL 按既有 fail-closed 不产 briefing;绑在一起 FAIL 场景就没有任何机器可读产物)。
3. **消费点三函数**:`compute_write_time_verdict`(写时算)/ `verify_candidate_for_journal`(`journal record` **预写入门** · 不读 journal ⇒ 无循环依赖)/ `verify_persisted_verdict`(事后审计 · 按 status 分岔)。
4. **真接线**:`journal/cli.py::_cmd_record` 是本仓当前唯一的 P2/O2 消费入口,已在 `store.save(entry)` 之前强制过门;`domain.JournalEntry` 加 `run_id`(向后兼容纯加法,旧行读回按缺失走 fail-closed)。

**PASS 仍结构性不可达且这是设计约束**:`compute_write_time_verdict` 生产路径只产 `FAIL`/`INSUFFICIENT_EVIDENCE`;单 run `enough_for_sampling=True` **也不会**变成 PASS(那要求「当前 epoch 有合法声明的 comparability_class」,池化基础设施在本仓尚未实装)。`pool_implemented` 恒 `False`,且消费点会拿**本 build 的 runtime 能力**去核对产物自报值 —— 产物不得自己证明自己的前置条件。

**本 task 不宣称**支持跨 run 池化判定或 `comparability_class` 验收(spec §1-O2(c) 转正条件①②,另行排期)。

**验收真跑**(逐条实跑 · 非口头):`pytest tests/ -k verdict -q` **58 passed** · `tests/test_journal_cli.py` **44 passed** · `tests/test_evaluate_cli.py` **18 passed** · 全量 **1134 passed**(基线 1075 · **0 回归**)· coverage(verdict/evaluate/journal)**93%** ≥ 85% · **18 处 mutation 逐条真跑证牙**:12 处当轮转红,**2 处首跑存活**(marker 多标记判据 / 审计路径摘要比对)→ 补测后同一 mutation 转红,**1 处预期存活**(`_fsync_dir` 目录项 fsync 是掉电持久性硬化、不是行为门,没有不靠真掉电就能测它的办法 —— 不编假测去盖住它),**3 处 round-4 finding 收口新增**(见 §2:每条各自单独 stash 掉修法 → 对应新测独立变红 → 恢复 → 全绿)。全过程逐条记 `tests/red-green-log/T042.log` + `tests/red-green-log/T042-round4.log`。
