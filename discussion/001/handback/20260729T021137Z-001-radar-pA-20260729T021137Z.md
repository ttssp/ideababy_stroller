### 2.2 🔴 **本模块的交付物是「那张边界表」,不是「C9 成立」的证明**

评审(**独立子代理 · 非 codex** · 4 轮)在**每一轮**都跑出一条**普通重构形状**的可用绕过 ——
**包括针对紧邻的上一版**。四轮共五条,且**第五条的修复本身又引入了第六个缺陷**:

1. 把跨次语料池放进**已分类的非评估包**(`journal/`)、落**已登记前缀**、用 `Path.open` 读 →
   四门全绿,三次同方向 dry-run 累积到 18 篇;
2. `sqlite3.connect(...)` 直接放进 `retrieval/` —— 名字白名单看不见;
3. 语料池落在 `out/` **之外**(`.radar-cache/`)—— ④ 与当时的行为门基线都只看 `out/`;
4. `a+` **增量扩展** + 走 **reconstruct** 入口 —— `a+` 可读却曾被算作纯写,而行为门当时只跑
   `evaluate`(⚠ 而且**我上一轮的测试把这个 bug 固化成了契约**,明写 `open(...,'a',...)` 不算读);
5. **bytes 路径让 ⑤ 全盲** —— `str(b"/p")` 得到 `"b'/p'"`,记录**看着有、比对时没有**;
   而 `dbm`/`shelve` **自己**就传 bytes。⚠ 最要命的是:第 1 条当初被判「可接受」的**理由正是
   「② + ⑤ 双红」** —— ⑤ 这半边一没,那条理由就不成立。**「靠另一道门兜底」这类论证本身要当心。**

五条现已全部关闭并成为**永久测试**。但评审与我的共同判断是:

> **这不是运气不好,是方法本身的上限。** 名字键控的 AST 审计器面对 `getattr` / 别名 /
> C 扩展 / bytes 路径**不可能完备**;audit hook 也只看得见自己订阅的事件、自己包住的窗口、
> 测试真驱动到的入口。**枚举出来的那张边界,就是交付物本身。**

模块 docstring 里已写死这句,以及三处**完全没覆盖的空白**(不是残留):分类边界不是
**import 边界**(① 对经 import 到达的读永久失明)· dry-run 把 retriever 换成 fake
(真 `OpenAlexRetriever` 里的缓存零行为覆盖)· ⑤ 对「只枚举目录不 open」的读法无痕。

## §4 方法论教训

1. **「靠另一道门兜底」是一种需要单独验证的论证。** 我把绕过 #1 的残留判为可接受,理由是
   「② + ⑤ 双红」。绕过 #5 直接打掉了 ⑤ 这半边 —— 于是那条判断在我不知道的情况下已经失效。
   **写下「由 X 兜底」时,必须同时验 X 在这条具体路径上真的有效。**
2. **修一半,而且是同一个 bug 的两条分支。** `io.open` 的 mode 下标 bug 我在限定名分支修过,
   却把非限定分支留着 —— 后者更糟:它不只是没过滤,是**拿任意路径文本制造假阴性**
   (`gzip.open("out/journal/raw-corpus.jsonl.gz")` 里那个 `w` 让它判成纯写)。
3. **修误报可以换来漏报,而漏报在守卫上贵得多。** 我修「参数遮蔽被误报」时用了整模块的
   shadowed 集合 —— 于是**另一个函数**里一句 `connect = None` 就静默关掉整份文件的检测。
   **FP 让人烦(还看得见),FN 让人以为干净。** 改成作用域感知后两头都对。
4. **测试会把 bug 固化成契约。** 绕过 #4 的一半根因是我上一轮的测试**明写** `open(...,'a',...)`
   不算读 —— 而 C9 的文字一直写着「读**以及 append 式增量扩展**」。实装与它自己的 docstring
   矛盾了整整一轮,而测试站在错的那边。
5. **文档的措辞是交付物的一部分,要和实装逐句对齐。** 「⑤ 是 API 无关的」这句话被证伪后,
   在**三个地方**残留(模块头、章节 banner、函数 docstring),其中函数 docstring 正是
   T040 作者会读的那一份。评审两轮都在追这句话。
