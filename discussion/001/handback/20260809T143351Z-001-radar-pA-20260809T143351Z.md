## §1 Rationale(执行摘要)

credibility/gate.py::_canonicalize_doc_ref 的 http(s) URL 分支在调 urlsplit 前补齐控制字符(TAB/CR/LF)预检 —— 复用 evidence/anchors.py::_has_forbidden_codepoint(import 而非二次实现)。此前 urlsplit 会静默删除内嵌控制字符,令畸形 ref 与真实语料 ref 折成同一 canonical key,让伪造锚在 _resolve_o2_anchor 的 membership 检查中冒充合法引用通过,绕过 P0.2 gate 要件③结构校验。消除两套独立 URL canonicalizer(gate.py 服务 P0.2 gate / anchors.py 服务 T021 证据链)的防御能力不对称。TDD:2 个新负向/端到端测试(负向:_canonicalize_doc_ref 单元级碰撞;正向:evaluate_gate 端到端证实攻击链可执行)先红后绿,全量 1014 passed(0 回归),gate.py 覆盖率 97%,ruff clean。评估复用可行性(task Outputs 强制项)结论:不做函数级更大范围提取——两函数契约本质不同(resolvable_doc_key 是结构验证+拒绝语义,canonicalize_doc_ref 是变体折叠+兜底语义),提取需要跨模块接口设计决策,超出本 task 授权;已复用的窄断言 _has_forbidden_codepoint 是唯一低风险且落在 file_domain 内的复用点。codex adversarial-review round 1 approve,0 finding。

## §2 触发原因 + 决议链(按 frontmatter `tags` 逐条说明)

### tag: feature

- **触发**:本 task(`FU-R5F4-gate-canonicalizer-hardening`)由 spec v0.8 amendment 的强制随行项
  (IDS 决议 40(5)「R5-F2/F4 第 6 轮 codex 复核」)在 round-3(`--base 8eda692 --scope branch`)发现,
  不是 v0.7 既有已知残留,是该轮复核新增证据。R5-F4(URL canonicalizer 大小写折叠修法)本身正确,
  但复核过程中发现该修法只落在 `credibility/gate.py`,与 `evidence/anchors.py` 的同类实现是**两套
  独立代码**,只有后者补了控制字符防御。
- **具体缺口(实测仍活 · 已用测试钉住)**:`src/radar/credibility/gate.py::_canonicalize_doc_ref`
  对 `http(s)://` URL 调用 `urllib.parse.urlsplit` **前不做控制字符预检**;CPython 的 `urlsplit`
  会**静默删除**内嵌 TAB/CR/LF。形如 `https://repo.example/a\tb` 的畸形 ref,经此函数处理后与真实
  语料 ref `https://repo.example/ab` 折成**同一** canonical key —— 让伪造的 `o2_traceable_ref`
  (以 `doc://` 前缀跳过 `_DOC_REF_PATTERN` 形状校验)在 `_resolve_o2_anchor`(gate.py:194)首跑只读
  模式的全语料 membership 检查中冒充合法引用通过,绕过 P0.2 gate 要件③「新证据链」的结构校验。
- **修法**:在 `urlsplit` 调用前加 `_has_forbidden_codepoint` 检查,命中 → 不折叠,原样返回逐字身份
  (fail-closed 方向)。直接 `import` 复用 `evidence/anchors.py::_has_forbidden_codepoint`(该函数
  已在 T021 build 期间为同一问题加固),而非二次实现 —— 避免与 KG-29(仓内已有 3 处 JSONL writer
  因未共享逻辑而漂移的先例)同型漂移。
- **TDD 证据**:2 层测试,均先红后绿。
  1. 单元级负向测试 `test_should_reject_control_character_collision_in_gate_canonicalizer`
     (TAB/CR/LF 三变体参数化)—— 直接钉 `_canonicalize_doc_ref` 层的碰撞。
  2. 端到端正向测试 `test_should_not_let_control_character_forged_ref_pass_readonly_doc_membership_via_gate`
     —— 直接调 `evaluate_gate`(首跑只读模式),证实修复前该攻击链**可执行**(gate 对伪造 ref
     返回 `passed=True`),修复后 `passed=False`。
  两测修复前均实测 FAIL(red),修复后 PASS(green)。
- **评估复用可行性**(task Outputs 强制项 · 非可选)结论:**不**做函数级更大范围提取。
  `evidence/anchors.py::resolvable_doc_key` 与 `credibility/gate.py::_canonicalize_doc_ref` 的契约
  本质不同 —— 前者是「结构验证 + 拒绝」语义(不可解析 → `None`,可解析 → 逐字身份,从不折叠任何
  变体);后者是「变体折叠 + 兜底」语义(DOI/arxiv 各写法折同一 key,不匹配任何强标识时原样返回,
  从不拒绝)。强行提取共享函数会让两侧调用方(gate.py 的 membership 比较 vs anchors.py 的结构校验)
  对返回值的假设冲突,需要更大范围的跨模块接口设计决策,超出本 task 授权(task doc 明确「若涉及
  跨模块接口变更需要更大授权,记录为独立 backlog 项,不在本 task 强推」)。真正低风险、已复用、且
  落在本 task file_domain 内的部分,是两者共有的窄断言 `_has_forbidden_codepoint`(本 task 已
  `import` 而非复制)。
- **与既有框架级发现的关系**:本 task 修复的缺口是 dogfood-backlog.md `KG-29`(「同一语义谓词
  `文档身份` 在多消费端各自实装 → 两套规则各自漂移,无 SSOT 也无漂移检测」)已记录模式的又一实例
  (KG-29 原文即已点名 `credibility/gate.py:72::_canonicalize_doc_ref` 是 anchors.py 的独立平行实现)。
  本 task 是 KG-29 项目级处置的一部分(关闭一个已知实例的具体差距),**不**新增 dogfood 条目记这点
  (会与 KG-29 重复)。
