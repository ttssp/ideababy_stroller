## §3 Suggested IDS actions

### A. ⛔ 需决议:judge 判断数**没有下界**,导致 P2 PASS 判据结构性不可达

spec §1-O2 (c) 要求「O2/P2 判 PASS 需 **≥3 条非豁免判断**供抽样」,但 **T020 的 judge 从未被
告知这个下界** —— prompt 只有 `JUDGE_MAX_JUDGMENTS = 12` 的上限。真跑实测 LLM 产 1 条。

这是**判据与产判据底料的那一环之间的缺口**,不是数据问题,也不是 T022 的实装问题。候选处置:

1. **起 FU 补 judge 下界**(改 T020 域):prompt 里显式要求「产 ≥3 条**互不重复**的结构成型度
   判断,每条各自挂锚」,并在解析后对「非稀疏却 <3 条」失败响亮或标记。
   ⚠ 风险:**逼 LLM 凑数** —— 把「本方向只有一条结论」硬拆成三条 = 制造低质量判断去满足计数,
   与 O4/OUT-8 的诚实精神冲突。需要一并想清楚「凑数」与「诚实少产」怎么区分。
2. **回 IDS 重议判据形态**:≥3 条是否是正确的抽样下界?对一个方法族高度收敛的方向,
   「一条结论 + 充分证据」可能比「三条稀释的结论」更符合 C6 的判断先行文体。
   若如此,§1-O2 (c) 的下界应改为**证据条数**或**锚覆盖度**而非判断条数。
3. 维持现状:承认 P2 PASS 需等 judge 侧改进,T022 的连通性证据先入账。

⚠ **这条与 KG-43 同族**(009 那次:预注册门槛被证数学不可达)——**判据可达性应先于判据冻结**。
本次是判据(≥3)冻结在先,而产判据底料的那一环从不知道它存在。建议 forge 一并考虑
「任何计数型验收判据,冻结前须验证产出侧被告知了该判据」。

## §4 方法论教训(建议与前几批一并回流)

1. **「某一环被调用」证明不了「它的输出被采用」。** 我写了一道自认为很强的门(断言 fake LLM 收到过
   全部 5 类 prompt),评审一个 mutation 就穿了:把 T012 精化结果丢掉、改用未精化叙事,
   prompt 照样都发了,门照样绿。**真正的判据是产物里有没有那一环的指纹。**
2. **fail-closed 的保证必须住在产产物的那个类里,不能住在某一个调用方里。** renderer 从不看
   `ship_blocked`,靠 CLI 挡 —— 今天没事,明天多一个消费者就漏。
3. **产物的 provenance 声明必须随运行模式变化。** dry-run 产物谎称「全链真跑」是最讽刺的一种
   自欺:反 PPV 的红线写在同一份 spec 里,而违反它的是产 PPV 证据的那份文件本身。
4. **诊断文案的盲区就是缺陷**(FU-KG30 那轮):只印响应开头,而截断证据全在尾部 → 白烧一次真调用。
5. **验证工具自身会失牙(第二次)**:等长 mutation(`8000 → 2000`)+ 秒级 mtime → `.pyc` 缓存
   不失效 → 跑陈旧字节码。已加 `PYTHONDONTWRITEBYTECODE=1`。(上一次是 `1 xfailed` 含子串 `failed`。)
6. **计数不足要查成因,不能顺手归给「数据稀疏」。** spec 把这条写进了 §1-O2 (c),本轮真用上了:
   一查就发现根本不是稀疏,而是产判据底料的那一环从不知道判据存在。
