## §2 触发原因 + 决议链(按 frontmatter `tags` 逐条说明)

tag = prd-revision-trigger:P0.2 gate 形态被 operator 拒的决议链如下。

触发条件:P0.2 gate 要求 operator 对重建叙事做盲测二值签字(要件①逐切片可信性 + ②识伪标阴性对照 + ③点名新证据链),三要件全满足才 PASS 解锁 T010/T011。operator 真跑填完要件①②后,拒填要件③并质疑 gate 形态本身 → 不产生有效签字 → gate 无法判 PASS。

operator 三条批评(真跑当面提出 · 原话 · forge 硬证据 · 非 agent 推演):
1. **operator 不是可靠打分器**:「即使我读了大量 diffusion 文章,我 cover 的领域也是有限的,我其实不是一个可靠的打分器」。→ 拿噪声大的人肉判据当二值硬 gate,统计功效低(单轮 3 切片 1 负控 · 瞎猜命中 1/3 · IDS moderator injection 77a5176 已自认此点)。
2. **应留痕可审计,不应盲测签字**:「文章有引用有结论有发现,是可以串起来的。你串的时候要留痕留证据,我可以快速审计校验,发现问题我跟你说,你有 log 和痕迹可以串联起来并调整」。→ operator 要的是"每条位移判断/边留 source trace + operator 抽查校验 + 发现问题 agent 有 log 可回溯调整",不是 blind 二值签字。
3. **应边用边迭代,不应前置一次性 gate**:「我倾向用的过程中发现问题解决问题回溯更新策略。现在做只能得到个 local 解,而且非常费时费力」。→ 反对"跑完 pipeline → 停 → 人肉盲判 → PASS 才解锁下游"的一次性闸门形态,倾向把验证嵌进使用流。

决议链(证据可回溯 · 对齐 O2 主锚):
1. 真跑命令:python -m radar.cli.reconstruct --direction "diffusion models" --slices 3 --from-date 2021-01-01 --to-date 2023-12-31(封闭历史窗回溯 · 与首跑同窗 apples-to-apples)。
2. 真检索/重建:OpenAlex 真返 + 真 DeepSeek 提炼 3 切片位移叙事(artifacts:out/reconstruct/diffusion-models-20260713T133341Z.md · run-877f1c1eaf9bdbd3042d631d22c99a08)。
3. operator 盲判:填要件①②(逐切片判定 + 识伪),拒填要件③(质疑 gate 形态 · 见上三条)。
4. gate 未判:无有效完整签字 → 不产 PASS/FAIL 数值,而是 operator 主动升级为治理层质疑。

诊断信号(供 IDS PRD 修订参考 · 本仓不决策):
- 与首跑(20260711)的区别:首跑 FAIL 是"pipeline 在此配置产不出新洞察"(能力问题 · 修 pipeline)· 本次是"gate 形态该不该存在"(结构问题 · 修 PPV 设计)· 两者不同层。
