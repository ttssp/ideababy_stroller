- 「ref 是幻觉 / 语料外」—— 真红线,该 STOP;

## §3 Suggested IDS actions

### A. ⛔ 需决议:`unlock-preflight` 的**角色**与 `resolvable` 谓词的**形态**

**问题陈述**:这道门的 PASS 不可复现(见 §2)。当前它同时被当作两种东西用,而这两种用法对可复现性的要求相反:

| 用法 | 出处 | 对可复现性的要求 |
|---|---|---|
| **一次性验收门**(绑定单个评估 run · 同一验收事件内跑完) | hand-back `20260718T231642Z` §4 「每评估 run 各自生效 · 非全局一次性」 | 不要求 —— 跑完即定 |
| **常驻 hard-block 门**(起下一个 task 前重跑) | HANDBACK-LOG:448 「起跑前重跑 unlock-preflight 作 hard-block 门」 | **强要求** —— 否则必然假 STOP |

**候选方向**(producer 建议,IDS 定):

- **A1 · 明确为一次性验收门,退出常驻用法**(改动最小)。协议层写死:该门只在「评估 run 产物落地的同一验收事件内」跑一次,结果绑 evidence bundle stem 写入 journal;后续 task 起跑前**不重跑**,而是**校 journal 里该 stem 的 PASS 记录存在**(纯本地读,可复现)。—— 这与设计本意一致,也与 `verify_selfcheck_journal` 的既有机制吻合。**producer 倾向此项。**
- **A2 · 让它可复现:证据面快照留档**。评估 run 落 audit 时,把当次检索的语料 ref 集**一并落盘 + digest**,作为 evidence bundle 的一部分;重跑时比对**快照**而非重新拉取。独立重拉降级为**带容差的一致性抽查**(如 ≥95% 命中即 PASS),用来反回声室而非当硬门。⚠ 代价:快照本身成为可伪造面(与 KG-B10 同族),需想清楚谁签它。
- **A3 · 谓词分裂**:把 `resolvable` 拆成「**幻觉检测**」(ref 是否为真实可解析文献 —— 与今日 top-N 无关)与「**语料一致性**」(与当次检索的重合度 —— 带容差)。前者当硬门,后者当告警。
- **A4 · 维持现状**(不推荐):则须在协议层明写「本门只可在评估 run 当日跑,过期即失效」,并把 HANDBACK-LOG:448 那类「起跑前重跑」的指令撤回。

⚠ **无论选哪个,请一并处理「门的分类」这个更一般的缺口**:目前 SKILL / spec 里没有「**一次性验收门** vs **常驻门**」的概念,于是同一个脚本被两种用法混用而无人察觉。
