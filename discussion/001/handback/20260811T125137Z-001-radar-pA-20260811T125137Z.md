## §2 修法

新增两个 writer(与既有 `briefing/writer.py` 同惯例):

- `graph/writer.py::write_graph_json` → `out/graph/<slug>-<ts>.json`(节点/边逐条含
  `source_ref`,供 O2 三击核对叙事里点名的具体节点/边是否真存在)
- `retrieval/writer.py::write_corpus_json` → `out/corpus/<slug>-<ts>.json`(每篇含
  title/authors/published/abstract/source_ref,供核对"检索语料 N 篇"具体是哪 N 篇)

抽取共享的原子发布 helper `radar/atomic_publish.py`(briefing/writer.py 已有的、多轮 codex
硬化过的"临时文件 → fsync → `os.link` 无覆盖发布"逻辑收敛到一处,graph/retrieval 两个新
writer 直接复用,不第三/四次复制粘贴)。`lifecycle/ephemeral.py` 新登记 `out/graph`/
`out/corpus` 为 `ArtifactClass.PRODUCT`(单次 run 交付物,非跨次累积语料库,C9 合规)。
`cli/evaluate.py` 非 `ship_blocked` 分支与 briefing 同一个 `ts` 落图/语料;`briefing/renderer.py`
新增可选构造参数,正文追加"产物核验"小节引用路径 + 计数。

**过程中发现并修复一处真实循环 import**:`atomic_publish.py` 原设计复用
`reconstruct/writer.py::_slugify`,但 `radar.retrieval`/`radar.graph` 都被 `radar.reconstruct`
包传递性 import(经 reconstructor→slicer→Paper),而 `atomic_publish` 又被这两个包的新
writer 调用,构成循环(实测 `ImportError: partially initialized module`)。改为在
`atomic_publish.py` 内联一份 `_slugify`(逻辑冻结、复制风险远小于给基础设施层引入跨包循环
依赖)。同一根因也出现在 `RunProvenance` 枚举类型上(见下节 round-1 finding),同样绕开。
